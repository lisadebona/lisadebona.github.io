Integration Guide

How to Obtain Your Gmail API Refresh Token

This step-by-step guide will help you quickly generate the required OAuth credentials (`Client ID`, `Client Secret`, and `Refresh Token`) so our mailer application can securely send emails on your behalf.

Before You Begin

Gmail or Workspace Account

Access to the Google account that will send outgoing emails.

Google Cloud Console Access

Ability to create or manage projects on Google Cloud.

Part 1

Create OAuth Credentials in Google Cloud Console

Crucial Warning on Test Status

If your app is in "Testing" publishing status, Google automatically expires refresh tokens after 7 days. To make your token permanent, either set your project status to "In Production" or use a Google Workspace domain.

Go to Credentials > Create Credentials > OAuth client ID.

  • Application type: Choose Web application.
  • Under Authorized redirect URIs, click Add URI and paste the following exact URL:
https://developers.google.com/oauthplayground
Part 2

Generate Refresh Token via OAuth Playground

On the left menu, scroll down to Gmail API v1. Expand it and select the required scope:

https://www.googleapis.com/auth/gmail.send

Click the blue Authorize APIs button. Log in with your target Gmail user and click Allow (If prompted with "Google hasn't verified this app", click Advanced > Go to App (unsafe) to proceed).

Part 3

Interactive Credential Configurator

Paste your tokens below to automatically format your configuration file. All data stays local in your browser.

Generated .env Snippet 
GMAIL_USER=user@example.com
GMAIL_CLIENT_ID=your_client_id_here
GMAIL_CLIENT_SECRET=your_client_secret_here
GMAIL_REFRESH_TOKEN=your_refresh_token_here

Security Best Practices & Token Expiration

Token Protection

Never check your `.env` file or Client Secret into public GitHub repositories. Keep these secret keys restricted only to authorized backend production environments.

Refresh Token Invalidation

Tokens will be automatically revoked if you change your Google Password, revoke app access under Google Security Settings, or leave testing mode inactive for 6 months.

Troubleshooting Common Issues

Error: "redirect_uri_mismatch"

Ensure `https://developers.google.com/oauthplayground` was added exactly under Authorized Redirect URIs inside your Google Cloud Console OAuth Client settings (make sure there are no trailing slashes or spaces).

Error: "403 Access Denied / Access blocked: App has not completed the Google verification process"

Make sure you added the target email address under OAuth Consent Screen > Test Users. If logging in with that account, click Advanced > Go to App (unsafe) on the consent popup.

Refresh token stops working after 7 days

Your Google Cloud Project is set to "Testing" mode. Change status to "In Production" on the OAuth Consent Screen page or use a Google Workspace domain account.
